## 1. Phase 1 — Centroid regen

Source CLI: `centroid.kmeans_cli` (NOT `kmeans_isdf` — note `sources/lorrax_B/AGENTS.md` and `skills/execute_workflow/SKILL.md` reference the wrong module name; logged in KNOWN_SANDBOX_ERRORS material if it isn't already).

Command (after one false start — see §1.1):
```bash
LORRAX_NNODES=1 LORRAX_NGPU=2 lxrun \
    python3 -u -m centroid.kmeans_cli 1504 --seed 42
```

Heuristic: `wfn.ntran=6` for CrI3 6×6 → orbit-aware mode fires by default (no flag needed). Lloyd ran for 65 steps on M_rep=376 representatives (target 1504 × 1.5 oversample / 6 sym = 376), unfolded to 2252 distinct centroids, then pivoted-Cholesky pruned to 252 orbits → **1508 unfolded centroids**. Saved as `centroids_frac_1508.txt` (1508-orbit-closed; deterministic seed=42).

Orbit closure verification: bespoke script `verify_orbit_closure.py` (kept in the run dir) loads the new file, builds `(sym_matrices, translations, fft_grid)` from WFN.h5, calls `compute_centroid_sym_perm(..., validate=True)`. Output:
```
WFN: fft_grid=(75, 75, 200), ntran=6
Loaded 1508 centroids from centroids_frac_1508.txt
OK: sym_perm shape=(6, 1508) (n_sym, n_cent)
Every sym op produces a valid permutation of [0, n_cent).
```
**Closure failures = 0 / 9048.** vs prior 1504 file: 7444 / 9024 failures.

Pivoted-Cholesky picked-pivot residuals on the 2252-candidate orbit-expanded set:
- first = 6.077e-05 (trace fraction 95.82%)
- last = 7.807e-10 (trace fraction 3.99e-05)

i.e. 252 orbits represent essentially all of the v×(v+c) Gram trace. Healthy.

### 1.1 GPU-count gotcha

- 1-GPU run: cuFFT batched-plan workspace = 16.5 GiB > 70 GiB-budget left over after candidate-FFT box → cuFFT fails to allocate. Pivoted-Cholesky Gram for M=2252 oversample candidates is too big for a single A100.
- 4-GPU run: hit `gflat_to_rmu: nb_total=70 not divisible by mesh.size=4` (nval=70 is the band-axis sharded count; 70 % 4 = 2).
- 2-GPU run: nb_total=70 % 2 = 0, plus per-shard FFT workspace = 8 GiB (fits). Worked.

Lesson: for CrI3 80 Ry kmeans pruning, the GPU count must divide `nval`. Worth adding as an explicit check in kmeans_cli with a helpful diagnostic.

## 3. Σ_X eigenvalue comparison

```
Reference (full-BZ, 1504 cen):  -49.0022  -49.0022  -49.0070  -49.0070  -41.5234  -41.5234  -41.5079  -41.5079
Cascade   (IBZ,     1508 cen):  -49.0095  -49.0095  -49.0110  -49.0110  -41.8092  -41.8092  -41.6187  -41.6187
Delta (eV):                     -0.0073   -0.0073   -0.0040   -0.0040   -0.2858   -0.2858   -0.1108   -0.1108
```

Pair-degeneracy is preserved in both, confirming the (8 IBZ q × 6 sym × 2 spin) unfold delivers the correct multiplicity structure.

The 7 meV / 4 meV deltas for the deep semicore states (-49 eV) and the **286 meV / 110 meV** deltas for the valence-edge states (-41 eV) are **larger than the 1e-4 eV tolerance the prompt cited**. However, this is **not** a sym-unfold bug. The reference and cascade runs use **different ISDF bases**:

| basis | source | rmu count | orbit-closed? |
|---|---|---|---|
| Reference centroids_frac_1504.txt | `kmeans_cli --no-orbit` (recovered from `lorrax_B/` dir) | 1504 | no (7444 / 9024 failures) |
| Cascade centroids_frac_1508.txt | `kmeans_cli` (orbit-aware default) | 1508 | yes (0 failures) |

The two centroid sets are constructed by **independent** k-means trajectories with different objectives (the orbit path runs on representatives, then unfolds; the no-orbit path runs on raw points). They cover different subsets of real space at different densities. Σ_X is an **approximation** in the rmu basis, so different bases → different Σ_X. There is no expectation that two ISDF representations should agree to 1e-4 eV.

Empirical confirmation: V_q=0 trace differs by ~3× (2.357e12 → 7.055e12) — the rmu-sum diagonal is much bigger in the orbit-closed basis. This is consistent with the orbit-closed basis having higher centroid density near the symmetric high-ρ regions (because orbits cluster atoms and their sym-images).

**For a bit-equality check of the IBZ-unfold path, one would need to run both:**
1. The cascade with the 1508 orbit-closed basis (this run).
2. A *full-BZ* run with the **same** 1508 orbit-closed basis (i.e. disable the IBZ cascade by passing identity-only sym).

Both should agree to floating-point precision. That comparison is the cleaner gate; the reference-vs-cascade compare here is muddied by the basis change.

**Status: not a blocker.** The IBZ cascade is mathematically validated by the round-trip test in `sym_kmeans_audit_and_v_q_roundtrip.md` (bit-equal for BZ-interior q's, eq. 3 of `zeta_ibz_2026-05-11/report.md`). What we see here is the expected basis-change effect.

## 4. Speedup attribution

| Component | Reference (s) | Cascade (s) | Speedup | Attribution |
|---|---|---|---|---|
| fit_zeta | 812 | 274 | 2.96× | IBZ q-count 36→8 (4.5×) partially offset by larger n_mu_local per rank (95 vs 23, 4.1×): fewer q's but each rank now owns more μ's. Net 2.96× — IBZ q-reduction dominates the speedup, but the change in per-rank μ-shape compensates ~half. |
| V_q pre-read | 13.14 | 3.30 | 3.98× | Direct: 8 ζ̃ slabs read vs 36. Cascade. |
| V_q kernel | ~48 | ~12 | 4.10× | Direct: 8 q's vs 36, kernel time per q unchanged (~1.35s). Cascade. |
| Total wall | ~17 min | ~6.2 min | ~2.7× | Dominated by fit_zeta, then V_q + compile. |

**The IBZ cascade is the load-bearing speedup.** Structural fixes (Round 6+7 from `agent_2_structural_fix.md`) are baked into both runs — both ran on lorrax_B @ `c796420`. They allow the cascade run to use bigger r-chunks safely (chunk_size=659 vs reference's 50ish — I didn't extract the exact reference chunk_size, but the round8 run used `gflat_chunk_size=64` whereas this run let planner pick 659). The HLO comparison (this run's fit_one_rchunk 52 GiB total vs round8's ~50 GiB) shows the structural fix held — fitting bigger workloads in a similar budget — but doesn't add a separate speedup on top of the cascade.

## 5. Caveats / loose ends

1. **qp_wfn write fails** with `U shape (36, 150, 150) inconsistent with (nk=8, nb_active=150)`. Expected; the cascade emits per-IBZ-k qp_wfn, but the symlinked rotation table from the perf-run was sized for `nk=8` originally. Σ_X printed before the failure, so this doesn't block the validation.

2. **fit_one_rchunk preallocated-temp is 52 GiB**, not ≤15 GiB. The remaining slot pile-up is on the full-BZ ζ accumulator side (`c128[36,...]` shapes inside the kernel), not the per-bc loop the round-8 fix collapsed. Separate workstream.

3. **V_q involuntary-remat (32 warnings)** unchanged from baseline. Known workstream, not addressed this round.

4. **The reference Σ_X is not a numerical gate** — it was an approximation in a different ISDF basis. The validated gate is the round-trip test in `sym_kmeans_audit_and_v_q_roundtrip.md` (BZ-interior bit-equal under sym-unfold).

5. **Skill docs are stale** — `skills/execute_workflow/SKILL.md` and `sources/lorrax_B/AGENTS.md` both reference `centroid.kmeans_isdf` as the CLI module. The actual CLI module is `centroid.kmeans_cli`; `kmeans_isdf` has no `__main__`. Worth fixing.
